## Verdict / 结论

All three items are closed and the front end now has the same CI rigour as its siblings. The new findings are the cost of that hardening: a source-level regex pre-scan rejects entity declarations even inside comments and CDATA, and this front end and YAML now diverge on how they accept the same semantic values.

三项全部关闭，且这个前端现在有了与兄弟模块同等的 CI。新发现是这次加固的代价：源码级正则预扫描连注释与 CDATA 里的实体声明也一并拒绝，而且它和 YAML 对同一语义值的接受面出现分歧。

### P3

**P3-1** — `src/Compiler.php (710 lines) vs spec.md`

- EN: Size against its own claim: `src/Compiler.php` is 710 lines for "read XML into an array IR", above the ~500 the spec suggests, and the file carries many per-point helpers (childList, readAttributes, assertNoAttributes, hasBareText). yaml-pages does the same job in 162 lines of src, which marks this as the place to converge.
- 中文: 与自身声明相比偏大：src/Compiler.php 为「把 XML 读成数组 IR」用了 710 行，超过 spec 提到的约 500 行，且逐点助手很多（childList、readAttributes、assertNoAttributes、hasBareText）。yaml-pages 用 162 行 src 做同一件事，说明这里是可以收敛的地方。
- Verification / 验证: reproduced / 已实证

**P3-2** — `src/Compiler.php:168-170 vs migears-pages/src/Compiler.php:541-545`

- EN: A section whose name is empty after trimming gets different wording from the YAML side: XML reports "sections[0]: section is missing its name attribute" while YAML reports "section name '   ' is empty; a layout can only fill a named section". The behaviours agree, the messages do not — against the parity test's own "same error, same wording" intent.
- 中文: section 名 trim 后为空的文案与 YAML 侧不同：XML 报 "sections[0]: section is missing its name attribute"，YAML 报 "section name '   ' is empty; a layout can only fill a named section"。行为一致、文案不一致——与对拍测试自称的「同错同文案」宗旨相悖。
- Verification / 验证: reproduced / 已实证

**P3-3** — `src/Compiler.php:561-578 vs migears-yaml-pages/src/Compiler.php:53-63`

- EN: The same semantic value is accepted differently by the two front ends: XML follows HTML boolean semantics, so `required="1"`, `"yes"`, `"on"`, `""` and `"required"` are all true, while YAML requires a native scalar and rejects `required: 1` (integer) and `rows: '4'` (quoted). Same contract, same value, one side legal, one side an error.
- 中文: 同一语义值在两个前端的接受面不同：XML 走 HTML 布尔语义，required="1"、"yes"、"on"、""、"required" 全为真；YAML 要求原生标量，required: 1（整数）与 rows: '4'（引号）都报错。同契约同值，一端合法一端报错。
- Verification / 验证: reproduced / 已实证

**P3-4** — `src/Compiler.php:85-91`

- EN: The entity pre-scan runs a regex over the raw source, so `<!-- <!ENTITY x "y"> -->` is rejected as an entity declaration even though libxml would ignore it — and the same inside CDATA. A false positive of the hardening.
- 中文: 实体预扫描对原始源码跑正则，因此 <!-- <!ENTITY x "y"> --> 也会被当作实体声明拒绝，尽管 libxml 本会忽略它——CDATA 内同理。这是加固带来的误报。
- Verification / 验证: reproduced / 已实证

## Test gaps / 测试盲区

The parity corpus is thin: 3 page pairs and 4 error pairs, so most shared-layer rules (required scope, field scope, duplicate option/data/section, attr names, section trim) are not cross-checked and single-sided regressions stay invisible.

对拍语料偏薄：只有 3 对页面与 4 对错误，因此共享层的大多数规则（required 作用域、field 作用域、option/data/section 重复、属性名、section trim）不在对拍范围内，单边回归无法被发现。
